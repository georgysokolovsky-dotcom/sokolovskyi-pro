# Условия участия и порядок внедрения

Комплект 2026-10-20-v1 подготовлен для новых заказов. Состояние: проект, публикация новых условий выключена. Дата вступления в силу и фактический процесс оформления заказа пока не установлены.

В публичный репозиторий включены обезличенные шаблоны. Полный комплект с реквизитами Исполнителя подготовлен отдельно в документах для владельца. Перед размещением полных текстов с налоговым номером, адресом и личным email в этом публичном репозитории необходимо отдельное разрешение владельца на такую публикацию. Незаполненные реквизиты также блокируют активный выпуск.

Три первых документа являются исходниками страниц. Остальные являются шаблонами для системы заказов и материалов программы. Цена, состав и сроки каждого тарифа заполняются в индивидуальных условиях. Пример или договорённость с одним участником не задают параметры всей программы.

Рабочий реестр процессов данных и лист решений владельца входят во внутреннюю часть предоставленного комплекта документов. Они не публикуются в этом репозитории. В публичную политику должны быть перенесены необходимые подтверждённые сведения в понятном участнику виде.

## Что меняется в сайте

Новые страницы расположены по путям `/legal/terms/`, `/legal/privacy/` и `/legal/withdrawal/`. При обычном режиме `enabled=false` они не создаются и не добавляются в footer. Режим `LEGAL_PREVIEW=1` создаёт помеченные страницы проекта с `noindex,nofollow` в отдельной папке `dist-legal-preview`. Обычная сборка создаётся в `dist`. Перед каждой сборкой `prebuild:astro` очищает только её целевую папку. Не используйте preview для production deployment.

Ссылки footer на четыре прежних страницы со статусом `unconfirmed` скрыты до подтверждения их содержания. Существующие маршруты сохранены. Действующая политика `/privacy-policy/` не заменена политикой участников.

Публичные страницы не осуществляют акцепт: здесь нет платёжных API, записей согласия в браузере или имитации оформления заказа.

После выпуска на страницах и в footer появляется одна проверенная общая ссылка «Мои условия» из `publication.myTermsUrl`. До подтверждения адреса и доступа только к своим заказам выпуск заблокирован. В preview показывается честный статус «Переход пока не подключён»; случайной или персональной ссылки нет. Общий урок Kwiga подготовлен без полей конкретного участника, с переходом в этот раздел. Подробности и сценарии проверки — в [контракте интеграции](my-terms-integration.md).

## Выпуск

1. Установить фактическое содержание услуг и требования рынков продаж.
2. Принять операционные условия будущих продаж и заполнить спецификацию продукта.
3. Установить реальные процессы обработки данных и заменить незаполненные сведения полными публичными разделами.
4. Подключить оформление конкретного заказа до оплаты и отправку неизменяемой копии покупателю в реальной системе продаж. Проверить общий вход в «Мои условия», сохранить `publication.myTermsUrl` без личных параметров и подтвердить `myTermsAuthorizationVerified` реальной проверкой изоляции заказов.
5. Проверить русскую и украинскую редакции, отдельные согласия и тексты уроков.
6. Заполнить [release](../../release/service-legal-release.json), установить дату начала применения, убрать статус проекта из текстов и обновить SHA-256 полного Markdown.
7. Включить `enabled` в `src/data/service-legal.js`, выполнить проверки и обычную сборку.

В release обязательны четыре фиксированных факта: `new_order_workflow`, `operating_terms`, `participant_data_processes`, `service_classification_and_market`. У каждого указываются значение, дата подтверждения и источник решения. Техническая проверка не подтверждает истинность этих сведений и не заменяет реального процесса оформления.

Новая редакция не изменяет исторические условия, платежи и доступы. Старые копии и подтверждения сохраняются. Для нового приобретения или изменения оформляется отдельный заказ либо надлежащее согласованное изменение.

## Проверка

```sh
node scripts/check-service-legal.mjs --self-test
npm run build:astro
node scripts/check-service-legal.mjs --dist dist
LEGAL_PREVIEW=1 npm run build:astro
LEGAL_PREVIEW=1 node scripts/check-service-legal.mjs --dist dist-legal-preview
npm run build:astro
node scripts/check-service-legal.mjs --dist dist
node scripts/check-service-legal.mjs --release
```

Последняя команда проверяет готовность активного выпуска даже при `enabled=false`. Для текущего проекта с незаполненными фактами её ненулевой код является ожидаемым результатом. Удаление массива фактов, пропуск документа, изменённый текст без нового хеша, маркеры `[УТОЧНИТЬ: ...]`, частная ссылка и неподтверждённая авторизация не должны проходить выпуск.

После preview перед deployment нужна повторная обычная сборка. В этом репозитории push в `main` запускает GitHub Pages deployment; заранее проверь актуальный workflow.
